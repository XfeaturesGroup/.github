# Support

## Product and account help

Use the support channel published by the affected product or service. Include
the product name, a concise description, relevant timestamps and non-sensitive
error identifiers where available.

## Open-source project help

For a reproducible defect, use the repository’s issue form. For setup and usage
questions, check the project documentation and existing discussions first.

## Security concerns

Do not use public issues for vulnerabilities, exposed credentials or suspected
account compromise. Follow [SECURITY.md](SECURITY.md) instead.

## What not to send

Never post passwords, API tokens, private keys, full session cookies, payment
details or unredacted personal data in an issue, discussion or pull request.
