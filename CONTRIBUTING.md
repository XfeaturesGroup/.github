# Contributing to XfeaturesGroup projects

Thank you for taking the time to improve a project. Start with the repository
README and any local contribution instructions; they take precedence over this
organisation-wide guide.

## Before you begin

1. Search existing issues and pull requests to avoid duplicate work.
2. For a substantial feature or behaviour change, open an issue or discussion
   first so the intended outcome and scope are clear.
3. Do not report vulnerabilities in public issues. Follow [SECURITY.md](SECURITY.md).

## Pull requests

Keep pull requests focused and explain the outcome, motivation and validation.
Include tests when behaviour changes. Update documentation when setup,
configuration, APIs or operational steps change.

Before requesting review:

- run the project’s relevant checks;
- avoid unrelated reformatting or generated-file churn;
- remove secrets and private environment data; and
- describe migrations, deployment dependencies and rollback considerations.

Maintainers may request a smaller scope, tests, documentation or a rebase when
needed for safe review. Submitting a contribution means you have the right to
provide it under the repository’s licence.

## Communication

Be specific, constructive and respectful. Keep review discussions about the
code and its impact. See [CODE_OF_CONDUCT.md](CODE_OF_CONDUCT.md).
